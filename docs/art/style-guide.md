## 影片觀察（來源記錄，不作現行配色規則）

**世界與場景**
- 日系與亞洲都市街區：高架鐵路、電線、招牌、便利店、自動販賣機、小貨車、欄杆。
- 場景是低多邊形大面積造型，配手繪感貼圖與少量像素化招牌與塗鴉。
- 植物用方塊狀、圓團狀葉叢，不追求寫實。

**角色**
- 部分角色呈現長腿、窄上身、寬褲、厚底大鞋；其他角色採較大頭、玩偶式比例，不能將影片全體概括成統一頭身比。五官簡化，專案的像素五官屬既有規格。
- 髮型是幾塊大面體的尖刺或斜片，辨識度高。
- 表面偏圖形化、簡化，服裝不依賴寫實布紋；影片局部仍可見反光與泛光。專案採霧面、避免金屬反射是既有美術規則。

**色彩與光**
- 日間：高飽和藍天、白雲、嫩綠、粉紅、黃色車身，整體明亮、乾淨。
- 室內與夜戲：偏暗，用黃色百葉窗光與紫、綠霓虹作對比，仍以平塗為主。
- 陰影大塊、柔邊，不用複雜光照。

**鏡頭與動態**
- 可見低角度仰拍、誇張廣角、貼地鏡頭（拍鞋、腿、褲腳）。廣角不等於魚眼；需確認是否有曲線畸變，才能稱為魚眼。
- 突然的特寫（臉、手、物件），再切到大景。
- 動作戲用速度線、旋轉鏡頭、誇張透視；日常戲則放慢，重心歪斜、晃動鞋尖。
- 畫面有少量復古（低解析、像素）感，與現代 3D 混合。

## 可直接使用的風格規則（對應角色設定稿）

1. 極低多邊形、少量大面，但模型要有完整厚度（不是紙片）。
2. 霧面平塗貼圖；五官用像素貼圖，表情可更換。
3. 比例約 6 至 6.5 頭身；四人有身高差（Jax 174 > Niko 168 > Vee 166 > Skye 162，見 `characters.md`）。
4. 角色服裝依 `../design/characters.md` 的個別規格：Jax 寬工裝褲、Vee 高腰喇叭褲、Skye 合身短褲配大腿中段過膝襪、Niko 寬口七分褲。影片中的寬褲觀察不作四人統一剪裁。去色後仍分得出四人：靠帽子與髮型、褲型、鞋型、配件、站姿。
5. 避免：寫實布紋、金屬反射、密集零件、遮住五官的常駐特效。
6. 鏡頭語言：低角度、廣角、貼地，作為標誌性演出。

## 技術建議（零基礎友好）

- 遊戲內使用「低解析渲染加放大」，自然得到階梯輪廓（Godot 可設定低解析 SubViewport）。
- 貼圖尺寸小（例如 64 至 128px），使用最近鄰過濾（Nearest），保留像素感。
- 單一角色面數目標：約 1,500 至 3,000 個三角面。

## 場景與鏡頭執行規則（現行）

- 城市維持「疊域」的垂直加建：貨道、橋樑、天台、欄杆、招牌、電線交錯；採乾燥日曬街頭與橋下灰綠陰影。
- 建築以暖白、灰石與青綠為大面；珊瑚遮陽棚、亮黃導向、嫩綠植物、販賣機和紙本告示提供生活重點。大面維持中低飽和、重點色提高飽和的分層規則見「JSR 目標規格」一節。
- 招牌可混用漢字、假名、拉丁字母與虛構符號，以印刷和塗鴉表現；中文採書面語。
- 遊玩維持單人固定斜俯視 ARPG，可辨識角色、敵人與預警；低角度廣角用於展示與演出，不能為模仿影片而破壞滑鼠移動與讀招。遊玩鏡頭的角度以「JSR 目標規格」一節為準。
- 像素感是呈現方式，不能代替輪廓、造型、配色和場景層次。現行保留 640×360 渲染設定，是否沿用待描邊測試決定（見「JSR 目標規格」）；未改為重度 CRT／VHS 濾鏡。

## 整體風格與三個分支

建議總述：**以日系街頭文化為核心，融合 Dreamcast／PS2 時代遊戲美術、低多邊形角色、非寫實渲染、誇張廣角鏡頭與音樂錄影帶式演出的風格化 3D。** 這是美術分類，不是確認影片使用當年硬體或特定引擎。

| 分支 | 造型與渲染觀察 | 配色與場景觀察 | 可借用的部分 |
|---|---|---|---|
| BRC／Video Project 1／Hinata | 修長四肢、大鞋、街服、幾何髮束；硬邊明暗、明顯輪廓線；滑板動作、計分 HUD、黃色圖形特效 | 青綠城市、灰白混凝土、藍天白雲；黃綠主體及紅色招牌；高架與天台形成垂直路線 | 動作輪廓、前景鞋子透視、城市層次、圖形化速度效果 |
| Ice Cream | 簡化動漫五官、厚底鞋、玩具感造型；較柔和明亮的簡化 3D；部分白背景人物展示 | 青藍天空、奶油色建築、嫩綠與粉紅；商店、販賣機、棋盤格地面、日常道具 | 生活細節、角色日常表演、明亮配色分支 |
| SLUMLORDZ | 稜角角色、黑西裝群像、機車與荒誕場面；局部保留體積光影 | 灰綠、黑、暗黃室內、橙紅天空、紫色燈光；擁擠街巷與室內 | 戲劇化透視、群像、黑色幽默與地下短片氣質 |

共同核心是輪廓、圖形與演出，而非堆疊復古濾鏡。不要只標「Y2K」：AI 可能轉向鍍鉻、透明塑膠與未來介面。不要一律標「PS1」：頂點抖動、仿射貼圖扭曲及抖色並未在這批已看素材普遍確認。

### 風格拆解規則

- **造型：** 先設計頭髮、衣袖、褲管與鞋子的輪廓，再補圖案；縮小或去色後仍要辨識角色。影片比例可不同，專案角色沿用既定 6–6.5 頭身及個別服裝。
- **幾何：** 建築與道具由大、中、小體積構成，圓形可保留稜角；不能只將高精度模型直接減面而破壞輪廓、關節與變形。
- **渲染：** 幾何簡化與卡通明暗分開決定。BRC 可測硬邊色階；其他兩支可保留柔和光影。禁止把所有分支套成同一種 toon shader。
- **材質：** 以印花、招牌、貼紙、窗格和色塊辨識物件，降低毛孔、纖維與微刮痕等資訊；專案仍遵守資產規格的純色／小貼圖與霧面要求。
- **配色：** 控制環境基調，以主角明度、色相和重點色突出人物；不要所有物件都同樣鮮豔。以上配色為視覺描述，未從原圖精確取 HEX 色票。
- **空間：** 高架、欄杆、天台、商店、招牌、電線建立前中後景與可移動路線；場景不能只靠日文招牌表達風格。
- **演出：** 廣角低機位、前景遮擋、姿勢重心與動作前後的停頓共同產生張力；遊戲遊玩鏡頭仍需考慮單人戰鬥可讀性，不能直接套用短片攝影機。

## 術語速查

| 英文 | 中文與用途 | 注意 |
|---|---|---|
| Stylized 3D | 風格化三維；總體分類 | 不代表特定面數或引擎 |
| NPR | 非寫實渲染；漫畫、插畫等渲染總稱 | 範圍比 cel shading 廣 |

| Cel / Toon shading | 賽璐璐／卡通著色；受設計的明暗層級 | 兩至三階是可試設定，非原片確認值 |
| Flat shading | 平面著色；以面法線表現稜角 | 不等於 cel shading |
| Hand-painted textures | 手繪貼圖；直接設計圖案與部分陰影 | 手繪感外觀不能證實原作者手繪流程 |
| Baked lighting | 烘焙光照；預先儲存部分光影計算 | 注意與動態人物光影的一致性 |

| Wide-angle / Foreshortening | 廣角／透視縮短；強調近大遠小 | 廣角不必有魚眼曲線畸變 |
| Dutch angle | 傾斜鏡頭；地平線傾斜 | 保持方向與空間可讀性 |

| Stepped animation | 階梯式動畫；姿勢跳變而非全程平滑插值 | 24fps 檔案不代表每兩格更新姿勢 |
| Speed lines / Impact frame | 速度線／衝擊幀 | 技術選項，需以具體鏡頭驗證 |
| Bloom / Color grading | 亮部泛光／調色 | 過量會破壞輪廓與分色 |
| HUD | 遊戲資訊介面；分數、連擊與動作名 | 後期或遊戲 UI 製作，避免 AI 生成文字失真 |
| Decal / Texture atlas | 貼花／貼圖集；招牌、貼紙與共用圖案 | 仍需符合貼圖預算 |

## 給 AI 的描述方法與可重用提示詞

### 提示詞結構

依序填寫：**輸出形式 → 主體 → 比例與服裝 → 場景 → 渲染 → 配色 → 鏡頭 → 動作 → 限制條件**。

先說清楚要概念圖、單一關鍵影格、角色三視圖、影片還是可交付模型；圖像提示詞不能視為模型拓樸或綁定交付規格。指定參考各自的用途，例如「A 只取渲染，B 只取配色，C 只取鏡頭」。角色身份、衣服和道具須以專案設定為準。

共用風格段落：

## JSR 街區 AI 製作方法（2026-11-05 補充）

來源：Alan 在本次對話提供的 JSR／BRC 場景製作文章。以下是吸收後的製作建議與提示詞，尚未執行場景生成或完成渲染驗證。採用任務拆分與明確技術規格；文章中的霓虹色票、20×40 米街區、六棟建築及滑軌是範例，不取代本專案已定色票、關卡和單人 ARPG 玩法。

### 將交付拆成三部分

| 部分 | 建議方法 | 交付與驗收 |
|---|---|---|
| 街區結構與材質測試 | 程式 AI 撰寫 Blender `bpy`，或在已連接的 Blender MCP 執行；方塊模組搭出街道、招牌框、鐵閘凹位、冷氣機和水塔 | 保留可重建腳本；檢查尺寸、通行空間、輪廓、三角面數；材質預覽與 Godot 實作分開 |
| 立面與塗鴉 | 圖像 AI 生成正投影立面及獨立圖案，再整理 UV 與透明度 | Base Color 不畫死強烈方向光；窗格、招牌和塗鴉可重用；文字另行排版 |
| 獨立街頭道具 | 方塊型道具優先直接建模；複雜造型可先出單體圖，再用有低面數功能的 3D 工具 | 圖生 3D 只作候選；檢查背面、底面、法線、UV、比例及實際三角面數，再匯出 GLB |

這是工作內容的拆分，不要求三個 AI 或三個供應商。單一 AI 可逐步協調；是否採用 MCP 或外部生成工具，取決於當次可用能力。圖生 3D 有利於控制正面造型，但單張圖仍無法確定背面結構，不保證一定比直接建模準確。

### 技術修正與專案限制

- **幾何：** 明確指定 `boxy primitives, no subdivision, flat shaded, sharp edges`。Flat Shading 控制法線表現，Cel Shading 控制明暗層級，兩者不同。欄杆及電線可由 Bezier Curve 加 bevel 產生，但要限制曲線與截面解析度，轉網格後再計算三角面數。
- **滑軌：** 一條管狀曲線只提供視覺幾何；真正可滑行仍需路徑資料、進出軌判定、速度、跳躍及碰撞邏輯。本專案目前只借用欄杆、電線與垂直街區的空間語言，尚未決定新增滑行玩法。
- **卡通明暗：** Blender 4.2+ 的 EEVEE 可用 `Diffuse BSDF → Shader to RGB → ColorRamp（Constant）→ Emission → Material Output` 測試兩至三段明暗。以中性 diffuse 計算光照，再配本色可避免直接用彩色光照結果作閾值。此節點流程不能直接匯出成 Godot shader，遊戲端需重建並驗證。
- **描邊：** Inverted Hull 需要向外擴張且法線反向的外殼、獨立深色材質及正確背面剔除。使用 Solidify 時必須核對 thickness、offset、翻轉法線、材質槽與 material offset；Backface Culling 是材質設定，不能只加 modifier 就視為完成。先套用物件縮放並檢查硬角破口、線寬、遠景遮擋及匯出結果；不必為每件小道具加黑線。
- **減面：** Planar Decimate 會溶解近共面的邊，可能產生 n-gon，**不等於轉四邊面**。5°–15° 只可作靜態候選網格的試驗範圍；保護 UV、材質邊界和輪廓，必要時手工重建。以匯出後三角面數驗收，不能只看 Blender polygon 數量。
- **預算：** 本專案維持道具 ≤500、建築 ≤1,500 三角面，貼圖 ≤128×128、純色優先。文章的道具 500–1,500 polygons 及 256／512px 貼圖只屬一般範例，不能直接當成本案新標準；描邊外殼也須列入幾何成本。
- **貼圖：** Blender 的 `Closest` 與 Godot 的 `Nearest` 要分別設定；最近鄰是美術選項，不是 JSR 風格的充分條件。正視圖投影只適合對應立面，側面、凹位與招牌仍需 UV；已做成幾何的冷氣機等細節不要又畫成立面上的第二套。
- **貼花與光影：** 白底圖不具透明 alpha，須另行去背或直接生成真正透明圖，並清理白邊。圖案採平塗本色，光照交由 shader；避免 `cinematic lighting`、`dramatic shadows` 等把強光影烘進貼圖的提示。保留 Base Color、減少寫實反射即可，並非不能使用任何 PBR 相容材質。

## JSR 目標規格（2026-11-05，待實測驗證）

Alan 要求補足 JSR 風格缺口。Alan 於 2026-11-05 已確認：目標為「真係似 JSR」（高飽和加粗線）、線色純黑、使用獨立測試場景。其餘數值為**設計預設值**，尚未在 Godot 實測；各數值在 `jsr-test.tscn` 測試場景中調整，定案後改寫此節，不另建檔。

### 目標

- 場景與線條以《Jet Set Radio》式風格為目標：**高飽和重點色、粗黑描邊、硬邊卡通明暗、塗鴉與街頭貼紙**。
- 參考證據仍以 BRC 影片為主，尚無 JSR 實際影格分析；不得宣稱已達 JSR 水準。滑行玩法不在本案內，只借用欄杆、電線與垂直街區的空間語言。
- 色票 HEX 不變，不重新引入藍紫基調；JSR 感由**飽和度分層、線條和明暗**達成。

### 飽和度分層（解決高飽和衝突）

| 層級 | 面積比例 | HSV 飽和度 | 內容 |
|---|---|---|---|
| 大面 | 約 60% | 0.15–0.45 | 暖白建築、暖石灰路面、灰綠陰影 |
| 中面 | 約 25% | 0.45–0.70 | 青綠店面與鐵構、嫩綠植物 |
| 重點 | 約 15% | ≥ 0.80 | 珊瑚遮陽棚、亮黃標記、塗鴉、招牌、販賣機、角色上衣 |

規則：每個基準畫面至少出現三組重點色塊；主角明度與色相必須與背景分離。天空允許提高飽和以貼近 JSR 的強對比。若測試後仍偏低飽和，優先加大重點層面積，其次才調整色票。

### 描邊

- **線色：純黑 `#000000`**（Alan 已確認，不用深墨綠）。
- **線寬（以 640×360 渲染像素計）：** 角色 2px、建築與大型物件外輪廓 1px、小道具 1px；遠景不再變細，但小於 8px 高的物件略去描邊，避免黑線吞掉物件。
- **做法：** 角色用反向外殼（法線外擴、背面剔除、純黑無光照材質）；場景因方塊硬邊會讓外殼破口，用螢幕空間深度加法線邊緣偵測。外殼與後製皆須計入幾何或效能預算。
- 敵人預警色、命中特效不得被黑線遮蓋。

### 卡通明暗（toon）閾值

以自訂 Godot spatial shader 取代內建 `DIFFUSE_TOON`，使用 N·L 做三段硬階（階間過渡不超過 0.02）：

| 段 | N·L 範圍 | 顏色 |
|---|---|---|
| 亮 | > 0.55 | 本色 |
| 中 | 0.15–0.55 | 本色與 `#243C38` 以 75:25 混合 |
| 暗 | < 0.15 | 本色與 `#243C38` 以 50:50 混合 |

暗部偏灰綠而非單純變黑。閾值為起點，以同模型、同燈光比較後調整。

### 鏡頭（解決鏡頭衝突）

- **以 2026-11-01 Alan 已定為準：固定 45 度等角，不可旋轉。** 預設 yaw 45°、pitch 45°。
- **現況差異：** 目前 `camera_follow.gd` 為透視 fov 55°，偏移 (0, 7.2, 10.3)，約 35° 俯角，且 yaw 為 0°，與上述不符。本次只記錄差異，不改 `main.tscn`；由測試場景比較「正交」與「低 fov 透視」兩種 45° 版本，待 Alan 確認後再改正式場景。
- JSR 式低機位廣角只用於展示鏡頭（另設相機），不用於遊玩。

### 解析度與描邊（解決 640×360 衝突）

測試矩陣：渲染解析度 640×360、960×540、1280×720，各配角色 2px／1px 線寬，並比較有無 FXAA。判準：1920×1080 螢幕放大後線條不呈階梯狀鋸齒、角色與預警仍可讀。**在測試完成前維持 640×360。**若測試顯示粗糙，改為較高解析度，並將線寬按渲染像素重算；像素感改由貼圖的 Nearest 過濾保留。

### 場景範圍與驗收畫面

- **範圍：** L 形街區約 24×40 米；4–6 棟建築（各 ≤1,500 三角面）；一段高架或天橋；欄杆與少量電線；至少一部販賣機、冷氣機、水塔、店面鐵閘、兩處塗鴉牆。道具 ≤500 三角面，貼圖 ≤128×128。
- **通行：** 玩家路線寬至少 4 米，容納戰鬥；不為滑行而將街道做得過窄。
- **測試場景：** 獨立的 `game/scenes/jsr-test.tscn`（已建立第一版，不修改 `main.tscn`）。按鍵：WASD 移動鏡頭目標、C 正交／透視、Tab 展示鏡頭、O 描邊開關、R 切換 640×360／960×540／1280×720。擷取：`xvfb-run -a godot --path . --rendering-method gl_compatibility --script tools/capture-jsr.gd`，輸出至 `docs/art/jsr/`。
- **第一版已知限制：** 螢幕空間描邊在 Compatibility 渲染器只能用深度（沒有法線），因此只有外輪廓，沒有立面內部折線；角色描邊為反向外殼，只在軟體渲染下看過；低角度展示鏡頭的地平線有粗黑線；飽和度分層尚未套用到場景顏色，目前仍是現行低飽和色票；只有遊玩與低角度兩張驗收畫面，缺角色近景。
- **驗收畫面：** 三張，每張同時以 640×360 及 1920×1080 擷取——(1) 遊玩鏡頭；(2) 低角度展示鏡頭；(3) 角色近景。逐項檢查：重點色三組以上、線寬達標、三段明暗可見、Jax 與背景分離、預警可讀。
- **回寫：** 記錄採用與未採用的設定及畫面證據，只更新本節。

### 最小驗證順序

1. **風格板：** 選一個參考面向作比較基準，標示要取用的輪廓、明暗、色彩和鏡頭；記下不取用的角色與版式。本次已決定採用共同街頭方向；後續調整同步回寫。
2. **角色與街角：** 使用一名既有角色與一小段街道，先檢查輪廓、身高、鞋型、個別服裝與前中後景。資產沿用角色 ≤3,000、道具 ≤500、建築 ≤1,500 三角面；貼圖 ≤128×128，細節見資產規格。
3. **著色比較：** 以相同模型、燈光與鏡頭比較既有霧面渲染與新增卡通色階測試，避免把不同建模誤判成 shader 差異。角色、背景分色需在實際遊玩距離檢查。
4. **鏡頭：** 做全景、人物近景和誇張廣角三種測試。全片幅等效 24–35mm 可作一般廣角起點，14–24mm 可測動作透視；這是建議值，不是原片鏡頭資料。遊戲鏡頭以單人戰鬥與預警辨識優先。
5. **動作：** 完成起勢、加速、接觸／落地、恢復的短片。使用清楚關鍵姿勢與重心；配件加少量跟隨動作。需要骨架動畫時遵循資產規格的動畫名與接入流程，不逕自破壞既有節點動畫。
6. **特效：** 用曲線、面向鏡頭的平面、Grease Pencil 或後製形狀建立速度弧線與爆發；不遮住五官與關鍵姿勢。
7. **整合：** 匯出 GLB，在 Godot 檢查尺寸、朝向、法線、材質、貼圖過濾、動畫與描邊。不能只看 Blender 預覽。
8. **回寫：** 記錄採用與未採用的測試、畫面證據及原因。只更新本檔同主題章節；實作規格變動同步到 asset-spec.md，角色變動回到 characters.md。

### 著色器、描邊與輸出注意

- 卡通色階的基本概念是將表面與光源的方向關係轉為明暗值，再映射至少量設計色階。兩至三階可作測試起點；不要將概念式當成已驗證的完整 Godot shader。
- Blender Eevee 可用 Shader to RGB＋ColorRamp 測試；不能直接照搬到 Cycles，也不能假設自訂節點會經 glTF 自動轉成 Godot 材質。
- 描邊可用反向外殼、Blender Freestyle／Line Art，或即時引擎的深度／法線邊緣偵測；工具輸出形式與相容性不同，選定後再做引擎驗證。遠景避免黑線吞掉小角色。
- 可選低解析 SubViewport 與 Nearest 放大，但需測試 UI、輪廓與實際遊玩距離的辨識；像素貼圖、抗鋸齒和渲染解析度分開控制。
- 滑板或手持物件的動畫可能需要約束切換：跟隨身體、獨立運動、再回到接觸位置。AI 影片難以穩定時以 3D 關鍵幀處理。
- Blender＋DaVinci Resolve 足以建立 3D／剪輯調色流程；大量圖形動畫可另用合成工具。這是工具建議，不是原作者工具紀錄。

### 只有製作網頁版本時才需要的技術

目前遊戲使用 Godot。下列是未來網頁展示或互動版本的選項，不代表遷移計畫：Three.js／React Three Fiber 載入 GLB；自訂 GLSL 著色；AnimationMixer 播放動畫；時間軸或 GSAP 控制鏡頭；HTML／CSS／SVG 製作 HUD；KTX2、Meshopt 等降低資產成本。Blender toon 節點通常需在網頁端重建或部分烘焙。固定展示影片可直接播放影片，不必先重建互動場景。
